  1. 서비스 개요 (디자인 기반 자동 추출 · 추정 포함)

  - 서비스명: Lee Suji Portfolio Page
  - 목적(추정): 웹 퍼블리셔·디자인·모션 역량과 프로젝트, 갤러리, 연락처를 한 페이지에서 보여주는 개인 포트폴리오
  - 대상(추정): 채용 담당자, 협업 제안자, 포트폴리오 방문자
  - 핵심 시나리오(추정): 방문자가 Home/Hero에서 소개를 확인하고, About Me에서 프로필·학력·자격 정보를 본 뒤, Team Project 01과 Skills,
    Gallery를 살펴보고 Contact/Footer에서 연락처를 확인한다.

  - 출처: 디자인에서 확인 + 디자인 기반 추정

  2. 구현 방식 및 기술 환경

  - 구현 방식: MPA
  - 프론트엔드: HTML + CSS + Vanilla JavaScript
  - 스타일링: 순수 CSS + CSS 커스텀 프로퍼티
  - 빌드 도구: 없음(순수 정적 파일)
  - 라이브러리: 없음. 디자인 컨텍스트에서 반복 캐로셀/슬라이더 구조 또는 명시적 애니메이션 구현 근거가 확인되지 않았으므로 GSAP·Swiper
    를 로드하지 않는다.

  - 데이터 저장: 없음 - 피그마에 보이는 정적 UI만 구현
  - 배포 환경: GitHub Pages
  - 출처: 사용자 선택 + 디자인에서 확인

  3. 디자인 구현 사양

  - 디자인 토큰: CSS 커스텀 프로퍼티(:root)로 색, 타이포, 간격, 라운드, 선, 그림자 값을 정의한다. 피그마에서 확인한 값만 토큰화하고 임
    의 값 사용을 금지한다.

  - 공통 컴포넌트: Site Navigation, Site Sub Navigation, 섹션 헤더, 배지, 버튼, 프로젝트 스펙 리스트, 스킬 카드, 갤러리 이미지 플레이스
    홀더, Contact/Footer 영역

  - 에셋: 피그마에서 확인된 이미지·아이콘·그래픽은 export asset으로 사용한다. Hero portrait image target, project image placeholder,
    skill illustration, gallery portrait placeholder, wave/pattern graphic은 디자인 치수와 비율을 유지한다.

  - 출처: 디자인에서 확인

  4. 핵심 화면 및 기능 명세

  - 화면: Header, Hero, About Me, Team Project 01, Skills, Gallery, Contact/Footer
  - 기능:
      - Header: 로고, 인용 문구, Home/About/Skills/Projects/Gallery/Contact 내비게이션, 검색 아이콘, 언어 표시, CTA 버튼, 하위 위치·미
        팅·팔로우 정보 표시

      - Hero: WEB PUBLISHER · DESIGN · MOTION 배지, 첫 파장 / NEXT WAVE 타이틀, 새로운 흐름을 읽고, 더 나은 경험을 설계하다. 설명, 2개
        CTA 버튼, 프로필 이미지 영역 표시

      - About Me: PORTFOLIO PROFILE 섹션, 프로필 정보 카드, 학력/교육 정보 카드, 자격증 정보 카드 표시
      - Team Project 01: 프로젝트 제목, TEAM PROJECT 01 · WEBSITE REDESIGN 배지, 기획서 보기, 사이트 보기 버튼, 프로젝트 이미지 영역,
        구현 기술·작업 기간·배포 매체·본인 기여도·브라우저 호환성·페이지 수·특징 목록 표시

      - Skills: Design, Web Publishing, Motion & Video 카드와 각 설명 표시
      - Gallery: 블랙 배경 패턴, 갤러리 타이틀/설명, 4개 세로형 이미지 플레이스홀더, 2개 버튼 표시
      - Contact/Footer: LET’S WORK TOGETHER, 설명, 전화번호, 이메일, Footer Email/GitHub, Copyright 표시

  - 동작:
      - 내비게이션 클릭은 해당 섹션으로 이동한다.
      - 기획서 보기, 사이트 보기, Contact/Footer 링크는 디자인에 연결 URL이 확인될 때만 실제 링크를 연결한다. 확인되지 않은 경우 임의
        URL을 만들지 않는다.

      - 애니메이션 및 캐로셀은 디자인에서 확인된 근거가 없으므로 구현하지 않는다.

  - 상태 처리:
      - 로딩: 로딩 없음 - 정적 UI라 별도 로딩 화면 없이 즉시 표시
      - 빈 데이터: 빈 데이터 없음 - 피그마에 있는 콘텐츠만 고정 표시
      - 오류: 오류 없음 - 외부 요청이 없으므로 오류 화면은 별도 구현하지 않음

  - 출처: 디자인에서 확인 + 사용자 선택

  5. 비기능 요구사항

  - 반응형: 피그마 1920px 디자인을 기준으로 데스크톱 우선 구현하고, 태블릿/모바일은 레이아웃이 깨지지 않게 재배치한다.
  - 접근성: 시맨틱 태그, 키보드 포커스, 이미지 대체 텍스트, 충분한 명도 대비를 적용한다.
  - 성능: 정적 파일 최적화, 이미지 용량 최적화, 불필요한 라이브러리 미사용을 적용한다.
  - 보안: 외부 입력/저장 없음. 외부 링크가 있을 경우 target="_blank" 사용 시 rel="noopener noreferrer"를 적용한다.
  - 출처: 사용자 선택

  6. 인공지능 작업 지시 순서

  - 1단계: MPA 기준 파일 구조를 먼저 제안한다. 예: index.html, assets/css/styles.css, assets/js/main.js, assets/images/, assets/icons/,
    assets/fonts/. 각 파일과 폴더의 역할을 설명한 뒤 구현한다.
  - 금지 사항:
      - 피그마에서 확인할 수 없는 텍스트·이미지·데이터·기능을 임의 생성하지 않는다.
      - 사용하지 않는 패키지나 외부 라이브러리를 추가하지 않는다.
      - GSAP·Swiper 외 애니메이션·캐로셀·UI 라이브러리·프레임워크를 추가하지 않는다.
      - 디자인에 애니메이션 근거가 없으면 GSAP를 로드하지 않는다.
      - 디자인에 캐로셀 근거가 없으면 Swiper를 로드하지 않는다.
      - MPA 구현에서 외부 프레임워크, 번들러, React, TypeScript를 사용하지 않는다.

  - 필수 규칙:
      - 제공된 피그마 디자인과 100% 일치하게 구현한다.
      - 레이아웃, 간격, 색, 타이포, 라운드, 이미지 비율, 컴포넌트 상태를 디자인 기준으로 맞춘다.
      - 웹표준과 일반 개발 관행에 따른 파일·폴더·명명 구조로 세팅한다.
      - 구현 전 파일 구조를 먼저 제안하고 각 파일의 역할을 설명한다.
      - HTML/CSS/이미지 파일·폴더는 소문자 케밥케이스를 기본으로 한다.
      - 에셋은 assets/images, assets/icons, assets/fonts 등 역할별 폴더에 정리한다.

  - 출처: 사용자 선택 + 고정 규칙

  - [ ] Hero Section의 배지, 타이틀, 설명, 버튼, 프로필 이미지 영역이 피그마 디자인과 시각적으로 일치한다.
  - [ ] About Me, Team Project 01, Skills, Gallery, Contact/Footer 섹션이 피그마 디자인의 순서, 크기, 여백, 카드 구조와 일치한다.
  - [ ] 데스크톱 1920px 기준 화면에서 전체 페이지가 피그마 원본과 시각적으로 대조 가능하며 주요 요소가 누락되지 않는다.
